# 第 14 章 组件耦合（Component Coupling）

## 本章讲什么

三条定律管组件**之间**的依赖：

- **ADP 无循环依赖原则**：组件依赖图必须无环。成环的组件事实上焊死成一个，
  没法单独发布/测试/理解。断环手法：DIP 插接口，或抽新组件。
- **SDP 稳定依赖原则**：依赖指向更稳定的方向。稳定 = 位置上的难改（被依赖越多越稳定）。
  量化：不稳定度 `I = 出向依赖 / (入向 + 出向)`，I=0 完全稳定，I=1 完全不稳定。
  I 大的可以依赖 I 小的，反之不行。
- **SAP 稳定抽象原则**：越稳定的组件应该越抽象（靠新增实现演化，而不必修改自身）。
  I-A 坐标图：理想在主序列对角线上；两个坏角落——
  **痛苦区**（稳定+具体+常变，典型：数据库 schema）、**无用区**（抽象+没人依赖）。

## 对照本项目

- **ADP**：Go 编译器把它做成语言规则（import 成环编译失败），包级免费。
  但**逻辑环**编译器管不到：Go↔Python 互调（respond / internal tools）是真实的
  跨进程调用环，靠协议纪律压住（Python 不碰 Go 的库、tools 只返回事实）——
  手工执行的 ADP。
- **SAP 痛苦区两位住户**：
  - `internal/model/*`：被全线依赖（I≈0）、100% 具体 struct（A=0）、每次加字段都要改
    ——第 8 章"字段涟漪"之痛的坐标系诊断：痛的根源是这个被全线依赖的包
    恰恰是变得最勤的包之一。书里点名的"数据库 schema"在本项目的化身；
  - `pkg/errcode`：同样 I≈0、A=0、随业务变——第 7 章那份"必须像标准库一样稳"
    合同的理论出处。
- 对照组：`AIResponder`——被依赖 + 纯接口，主序列上的模范生。
- 痛苦区里躺着一些不得不躺的东西（schema 即典型）；认识到它在那、改它时多一分
  敬畏（对拍测试、让 AI 干机械部分），就是务实的全部。

## 讨论沉淀（2026-07）

### wire/ 的坐标：I≈1 的模范生

wire 依赖全项目几乎每个包（出向拉满）、被依赖≈0（只有 cmd/server 的 main）——
全项目最不稳定的位置，但每根箭头都指向更稳定处，SDP 全合规。它具体（A=0）却
不受"无用区"判罚——那两个区惩罚的是被依赖的组件，没人依赖 wire。

至此 Main 组件的理论闭环凑齐：**最脏（全是 new 具体类）、最外圈（箭头全向内）、
最不稳定（I≈1）、随便改（无人受牵连）——四个描述说的是同一件事，且理应如此。**
系统总得有个地方吸收所有脏活，架构的艺术是让脏活集中在无人依赖的角落。

### Part IV 三章串成一句话
